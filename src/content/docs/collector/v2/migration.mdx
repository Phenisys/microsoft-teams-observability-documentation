This guide covers migration from the v1 agent (`pheniScript_Teams.py` / standalone binary with global flags) to the current v2 collector (`ms_teams_observability` with sub-commands).

## Major Changes

| Topic | v1 | v2 |
|---|---|---|
| CLI | Global flags (`--config`, `--ignore_state`, …) | Sub-commands (`run`, `validate`, `service`, `state`, `test-connection`) |
| Configuration | Legacy keys (`microsoft_*`, `ms_teams_*` features) | Typed keys (`microsoft_authentication.graph`, short feature names) |
| Config migration | YAML rewritten on disk | In-memory only — file not modified |
| State | JSON per tenant (`state/state_<tenant>.json`) | SQLite (`state.db`) with deduplication + outbox |
| Linux service | `--enable_boot_start` / `--disable_boot_start` | `service enable-service` / `service disable-service` |
| `site_definition` feature | Supported | Removed (ignored) |

## CLI Command Mapping

| v1 | v2 |
|---|---|
| `ms-teams-agent --version` | `ms-teams-agent --version` |
| `ms-teams-agent --config config.yaml` | `ms-teams-agent run --config config.yaml` |
| `ms-teams-agent --config config.yaml --call_id <ID>` | `ms-teams-agent run --config config.yaml --call-id <ID>` |
| `ms-teams-agent --config config.yaml --ignore_state` | `ms-teams-agent run --config config.yaml --ignore-state` |
| *(implicit at startup)* | `ms-teams-agent validate --config config.yaml` |
| *(no equivalent)* | `ms-teams-agent test-connection --config config.yaml` |
| *(no equivalent)* | `ms-teams-agent state show` / `reset` / `export` |
| `--enable_boot_start` | `service enable-service --config <path>` |
| `--disable_boot_start` | `service disable-service` |
| `--service_name_suffix=-prod` | `--instance prod` |
| `--force_service_creation` | `--force-service-creation` |

## Minimal v2 Configuration

```yaml
microsoft_authentication:
  graph:
    tenant_id: "<tenant_id>"
    client_id: "<client_id>"
    client_secret: "<client_secret>"
    scope: "https://graph.microsoft.com/.default"
    grant_type: "client_credentials"
  vaac:
    username: "<vaac_username>"
    password: "<vaac_password>"

license:
  filepath: "/etc/ms-teams-observability-agent/license.json"

output:
  console:
    enabled: true

collection_config:
  max_call_duration_hours: 5
  interval_collection_minutes: 1
  log_level: "INFO"
  features:
    calls_collection:
      enabled: true
    issues_collection:
      enabled: false
    pstn_calls_collection:
      enabled: false
    direct_routing_calls_collection:
      enabled: false
    autoattendant_collection:
      enabled: false
    callqueue_collection:
      enabled: false
```

<Aside type="note">
v2 accepts v1 legacy keys via an internal migrator, but this compatibility is transitional. Write v2 keys directly for new deployments.
</Aside>

## State Migration

v2 does not read the v1 JSON state (`state/state_<tenant>.json`) automatically at startup. You can still migrate v1 state manually with the temporary CLI command:

```bash
ms-teams-agent state migrate-v1 --source ./state-v1.json
```

See [Temporary Migration Command](/collector/v2/cli/#temporary-migration-command) for details and non-interactive flags.

If you prefer a clean cutover, starting with a clean state remains a valid path:

```bash
ms-teams-agent run --config ./config.yaml --ignore-state
```

Then run continuously:

```bash
ms-teams-agent run --config ./config.yaml
```

## Recommended Cutover Procedure

1. Back up v1 config, license, state JSON, and any service scripts.
2. Create a `config.yaml` in v2 format using the key mapping above.
3. Validate the config:
   ```bash
   ms-teams-agent validate --config ./config.yaml
   ```
4. Test Graph auth and exporters:
   ```bash
   ms-teams-agent test-connection --config ./config.yaml
   ```
5. Optional — dry run without exporting:
   ```bash
   ms-teams-agent run --config ./config.yaml --dry-run --ignore-state
   ```
6. Switch to production run or systemd service.

## Linux Service Migration

| v1 | v2 |
|---|---|
| `sudo ms-teams-agent --config <path> --enable_boot_start` | `sudo ms-teams-agent service enable-service --config <path>` |
| `sudo ms-teams-agent --config <path> --disable_boot_start` | `sudo ms-teams-agent service disable-service` |
| `--service_name_suffix=-prod` | `--instance prod` |
