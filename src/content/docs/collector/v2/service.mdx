Use this page to run the collector as a background service on Linux.

## Prerequisites

- Linux host with `systemd`
- Root privileges (`sudo`)
- Valid collector config file

## Recommended License Path

```bash
sudo install -d -m 0750 /etc/ms-teams-observability-agent
sudo install -m 0640 -o root -g ms-teams-observability-agent \
  ./license.json /etc/ms-teams-observability-agent/license.json
```

```yaml
license:
  filepath: /etc/ms-teams-observability-agent/license.json
```

<Aside type="caution">
Avoid storing the license under `/home/...` because service hardening can block access.
</Aside>

## Secrets in the service environment

A reference such as `${env:GRAPH_CLIENT_SECRET}` in the configuration is resolved from
the environment of the collector process. For a systemd service, provide the secrets with
a drop-in that reads a root-owned file, instead of writing them in the installed YAML:

```bash
sudo install -d -m 0755 /etc/systemd/system/ms-teams-observability-agent@default.service.d
sudo tee /etc/systemd/system/ms-teams-observability-agent@default.service.d/secrets.conf >/dev/null <<'EOF'
[Service]
EnvironmentFile=/etc/ms-teams-observability-agent/secrets.env
EOF

# root:ms-teams-observability-agent 0640 — one KEY=value per line
sudo install -m 0640 -o root -g ms-teams-observability-agent \
  ./secrets.env /etc/ms-teams-observability-agent/secrets.env

sudo systemctl daemon-reload
sudo systemctl restart ms-teams-observability-agent@default.service
```

```bash
# /etc/ms-teams-observability-agent/secrets.env
GRAPH_CLIENT_SECRET=...
SPLUNK_HEC_TOKEN=...
```

<Aside type="note">
The service installation validates the configuration with `--skip-secrets`, so the
secrets do not need to exist at installation time. They must be present when the service
starts: the collector refuses to start when a referenced variable is missing from its
environment. Keep the file readable by the service group only — the collector never
writes resolved values back to disk.
</Aside>

## Enable the Service

```bash
sudo ms-teams-agent service enable-service --config /absolute/path/config.yaml
sudo ms-teams-agent service status
```

## Enable a Named Service (Optional)

```bash
sudo ms-teams-agent service enable-service \
  --config /etc/ms-teams-observability-agent/prod.yaml \
  --instance prod

sudo ms-teams-agent service status --instance prod
```

## Common Operations

```bash
sudo ms-teams-agent service status --instance default
sudo ms-teams-agent service restart --instance default
sudo systemctl status ms-teams-observability-agent@default.service
sudo journalctl -u ms-teams-observability-agent@default.service -f
```

## Update Configuration Safely

<Steps>
1. Back up your config file.
2. Install updated config:

   ```bash
   sudo ms-teams-agent service install-config \
     --config /etc/ms-teams-observability-agent/prod.yaml \
     --instance prod \
     --service-restart-if-active
   ```

3. Verify status and logs.
</Steps>

## Disable the Service

```bash
sudo ms-teams-agent service disable-service --instance default
```

<Aside type="danger">
Disabling a service instance removes its local service data for that instance.
</Aside>
