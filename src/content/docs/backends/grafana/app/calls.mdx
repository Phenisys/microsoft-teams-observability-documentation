The Calls tab displays a filterable, sortable list of every call recorded by the collector.

**Default time range:** Last 6 hours.

## Filter Bar

Advanced chip-based filters using the key/operator/value pattern:

- **Key**: call property (type, health, participant, duration, etc.)
- **Operator**: comparison operator (equals, contains, greater than, etc.)
- **Value**: filter value

Multiple filters can be combined. A **"Show empty calls"** checkbox includes calls with missing metadata.

Filters are URL-synced (`?filter=...&showEmptyCalls=...`) for bookmarkable queries.

An **Update** button applies changes — the table refreshes automatically.

## Calls Table

| Column | Description |
| --- | --- |
| **Call ID** | Unique identifier (click to open Call Overview) |
| **Start / End** | Call timestamps |
| **Duration** | Call duration |
| **Organizer** | UPN or display name |
| **Type** | P2P or Group |
| **Participants** | Participant count |
| **Health** | Good, Poor, or Unclassified |
| **Media** | Audio, video, screen sharing used |
| **Client** | Teams client versions |
| **Endpoints** | Device types |
| **Root Cause** | Quality degradation cause (if poor) |

## Call Overview Drilldown

Clicking any Call ID opens the Call Overview as a drilldown page (not a separate tab). The breadcrumb shows **Calls → Call `{id}`** for easy navigation back to the list.

The Call Overview provides:
- **Verdict header**: call ID, timestamps, duration, organizer, participant count, quality KPI
- **Call Map**: geographic view of participants (GeoIP optional)
- **Evidence panel**: stream quality classification table with metric/value/threshold
- **Streams table**: per-stream metrics (RTT, jitter, packet loss, codec)
- **Call Timeline**: stream overlap visualization
- **Network diagnostics**: IP insights, ASN distribution, shared IP patterns, relay usage
- **Endpoint matrix**: per-participant platform, device, audio signals, CPU, client version

<Aside type="tip">
The time range from the Calls list is preserved when navigating to Call Overview and back. The URL carries `from`/`to` and `parentFrom`/`parentTo` parameters.
</Aside>
